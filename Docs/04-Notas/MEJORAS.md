# Mejora-02

## Correr en Supabase el ALTER TABLE de VETERINARIO.IdComercio y cargar los datos existentes

Al implementar la [[Plantilla-Historia|HU-169]] (CRUD de Servicios) se detectó que
`VETERINARIO` no tenía ninguna columna que lo ligara a la clínica donde ejerce, así que al
agendar una cita sin veterinario fijo el sistema podía asignar cualquier veterinario de toda
la base de datos, de cualquier veterinaria. El código ya espera la columna nueva
(`Veterinario.IdComercio` en EF, validaciones en `ServicioService` y `CitaService`), pero
falta:

1. Correr en la Supabase real:
   ```sql
   ALTER TABLE public."VETERINARIO" ADD COLUMN "IdComercio" integer NULL REFERENCES public."COMERCIO"("IdComercio");
   ```
2. ~~Actualizar a mano (UPDATE directo) el `IdComercio` de los veterinarios que ya existen —
   no hay CRUD de `VETERINARIO` todavía~~ — **ya no es necesario hacerlo a mano**: se agregó
   `VeterinarioController`/`VeterinarioService`, así que un Admin (a cualquier veterinaria
   afiliada) o un Funcionario (solo a la suya) puede vincular un veterinario existente
   buscándolo por correo desde el panel "Veterinarios" — ver [[Diagrama-Componentes]] §
   `/api/veterinario`. Solo hace falta correr el `ALTER TABLE` del punto 1 para que ese panel
   funcione; los veterinarios que ya existían en la BD antes de la columna simplemente
   aparecen sin veterinaria asignada hasta que alguien los vincule desde ahí.

Hasta que se corra el `ALTER TABLE`, cualquier endpoint que toque veterinarios (crear/editar
servicio, `veterinarios-comercio/{id}`, todo `/api/veterinario`) va a fallar con un error de
columna inexistente.

### Contexto relacionado
- [[Modelo-Datos]] § VETERINARIO — detalle completo de la columna y la razón de no usar
  `CARGO_CAT`/`COMERCIO_FUNCIONARIO` en su lugar.
- [[Diagrama-Componentes]] — endpoints de `/api/servicio` y `/api/veterinario` que dependen de
  esta columna.

### Estado
Pendiente solo el `ALTER TABLE` en Supabase (fuera del alcance de lo automatizable desde el
código). El resto —CRUD de vinculación desde la app— ya está implementado.

# Mejora-03

## Correr en Supabase el CREATE TABLE de SOLICITUD_TIPO_SERVICIO

Antes, tanto Admin como Funcionario podían crear tipos de servicio directo en
`TIPO_SERVICIO_CAT`. Ahora el Funcionario ya no puede: debe enviar una solicitud
(`POST /api/tiposervicio/solicitar`) que un Admin aprueba o rechaza desde el mismo modal
"Tipos de servicio" del panel de Servicios (badge con la cantidad de pendientes). El código ya
espera la tabla nueva (`SolicitudTipoServicio` en EF, `TipoServicioService`), pero falta
correr en la Supabase real:

```sql
CREATE TABLE public."SOLICITUD_TIPO_SERVICIO" (
  "IdSolicitudTipoServicio" integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "Nombre" varchar(100) NOT NULL,
  "IdUsuarioSolicitante" integer NOT NULL REFERENCES public."USUARIO"("IdUsuario"),
  "IdComercio" integer NULL REFERENCES public."COMERCIO"("IdComercio"),
  "IdEstadoSolicitud" smallint NOT NULL DEFAULT 1 REFERENCES public."ESTADO_SOLICITUD_CAT"("IdEstadoSolicitud"),
  "FechaSolicitud" timestamp NOT NULL DEFAULT now(),
  "FechaResolucion" timestamp NULL,
  "IdUsuarioResolvio" integer NULL REFERENCES public."USUARIO"("IdUsuario")
);
```

No hace falta insertar nada en `ESTADO_SOLICITUD_CAT`: reutiliza los mismos valores
1=pendiente/2=aprobado/3=rechazado que ya usa `COMERCIO`, que ya existen en la Supabase real
(confirmado porque `ComercioService.RechazarComercioAsync` ya los usa en producción).

Hasta que se corra el `CREATE TABLE`, `/api/tiposervicio/solicitar` y todo lo bajo
`/api/tiposervicio/solicitudes/*` va a fallar con un error de tabla inexistente.

### Contexto relacionado
- [[Modelo-Datos]] § SOLICITUD_TIPO_SERVICIO — detalle completo de la tabla y por qué no se
  mezcló el flujo dentro de `TIPO_SERVICIO_CAT`.
- [[Diagrama-Componentes]] — endpoints de `/api/tiposervicio/solicitudes/*`.

### Estado
Pendiente solo el `CREATE TABLE` en Supabase. El resto —flujo completo de solicitud, revisión,
aprobación/rechazo, y la UI en el panel de Servicios— ya está implementado.
